# DOFBOT 数据采集台 v0.1.7.post1 · 使用与安装说明

## 1. 用途与适用范围

软件运行在机器人自身 Linux 桌面，通过触摸屏操作。工作流程是：**手拖记录关节示教 → 保存示教 → 自动回到本条起点并回放 → 同步记录 RGB、实际关节状态和真实执行目标 → 人工审核保存 episode**。

不需要 VS Code、Codex、开发者的对话记录或付费账户。没有自动识别方块、视觉规划、碰撞检测、重力补偿或 VLA 训练功能。适合先验证“抓起方块放入固定盒子 / 指定标识区域”等桌面任务的数据流程。

| 项目 | 已确认条件或限制 |
|---|---|
| 机器人 | 本机为 DOFBOT-PRO，Jetson Orin 8GB，Ubuntu 22.04，1280×800 触屏 |
| 版本 | GitHub分发修订 v0.1.7.post1，源于 v0.1.7；已做路径去标识与本机预览默认限制，非原发布包逐字节副本 |
| Python / GUI | 本机 Python 3.10.12、PyQt5 5.15.6；使用系统 Python |
| 其他依赖 | 本机 OpenCV 4.5.4、NumPy 1.21.5、Arm_Lib 1.0.3、FFmpeg 4.4.2 系列 |
| 接口 | 真机适配器固定 I2C bus 7；使用厂家接口和本工程 0x15 通信约定 |
| 相机 | Orbbec DaBai DCW2 的 RGB UVC 路；不保存深度、IR 或点云 |
| 双摄 | 软件模拟流程已验证；尚无第二台实体 RGB 相机，需接入后另做硬件验收 |
| 其他设备 | 未验证，不因为也是 6 关节就可以直接套用驱动 |

本包只有源码、测试、启动辅助工具与文档，不含系统依赖、厂家 SDK、系统镜像或个人采集视频。Windows 负责解压、阅读、编辑、SSH 上传；本软件不是 Windows EXE。

## 2. 操作前必须分清的状态

| 状态或按钮 | 含义 |
|---|---|
| 关节在线 / SDK 反馈有效 | 表示读数有效；不证明已经抱紧、具有抓持力或路径安全 |
| 松力 | 全臂与夹爪关闭扭矩，没有重力补偿；肩肘、末端必须可靠支撑 |
| 抱紧指令已发 / 待现场确认 | 已请求开启扭矩，仍需现场观察，继续支撑，再按“确认已抱紧” |
| 初始位置 | 用户保存的全局姿态，不是修改舵机零位或厂家标定 |
| 本条起点 | 当前示教第一帧真实角度，可以不同于全局初始位置 |
| 停止动作 | 不再发送后续目标；不自动松力、抱紧或回位 |
| 软件急停 | 锁定本软件后续位置及扭矩指令，需人工复位；不切电 |
| 保存人工示教 | 保存手拖关节时间序列，还没有本条回放视频 |
| 保存此次数据 | 保存一次自动执行的图像、状态、执行动作和结果标注 |

不能靠“以前断电仍保持”推断松力安全，也不要用手硬掰已抱紧关节来测试。松力夹爪没有主动夹持力，手动合上不等于自动回放一定夹得住。

“5秒内回初始”受软件限速和反馈监测约束：通常请求 4.5 秒运动再做稳定检查，准备倒计时另计；跨度过大或反馈异常会拒绝 / 停止，不承诺任意姿态 5 秒内到达，不提供碰撞检测。

## 3. 安装与启动

在 GitHub 仓库首页选 Code → Download ZIP，完整解压；私有仓库需要维护者邀请接收方的 GitHub 账号后才能下载。也可用已有 GitHub 登录方式正常克隆。不要将令牌写入 URL 或脚本，不上传 SSH 密钥。

将完整目录通过 SFTP 上传到机器人用户主目录，目录示例取名为 dofbot-touch-collector。Windows 仅阅读、编辑与上传，下面命令均在机器人 Ubuntu 图形桌面终端执行：

```bash
cd ~/dofbot-touch-collector
/usr/bin/python3 verify-package.py
/usr/bin/python3 check-environment.py --demo
bash launch-demo.sh
```

需要通用组件时，优先复用厂家系统 Python；Ubuntu 22.04 可按缺失情况安装：

```bash
sudo apt update
sudo apt install python3-pyqt5 python3-opencv python3-numpy ffmpeg v4l-utils fonts-noto-cjk
```

真机另需厂家匹配的 Arm_Lib、smbus、I2C bus7 和设备权限，不从名称相似的任意包替代厂家库。不要以 sudo 启动 GUI 来绕过权限，不随意升级 Qt/OpenCV/CUDA。

先在模拟模式熟悉，再退出其他控制程序，固定现场，执行：

```bash
/usr/bin/python3 check-environment.py --real
bash launch-robot.sh
```

真机启动只读，不自动上力或运动。仍需按现场状态确认抱紧。不要无人值守测试松力/运动。

桌面图标默认创建模拟入口；显式 --real 创建真机入口，两者只创建图标，不启动应用：

```bash
/usr/bin/python3 install-shortcut.py
/usr/bin/python3 install-shortcut.py --real
```

创建后保持目录位置不变。真机数据默认 ~/dofbot-data/touch_collector，日志 ~/dofbot-data/reports/touch_collector.log；模拟数据为仓库内 demo-data。可自定义：

```bash
COLLECTOR_DATA_ROOT="$HOME/my-dofbot-data" bash launch-robot.sh
```

恢复标记在 software/.learning_session.json，独占锁在 software/.teleop_record.lock。请使用同一套软件和数据目录；不靠删标记、换副本或删 safety.json 绕过保护。不同副本的锁不能防止彼此占用同一设备。

已有正式安装的机器人不要覆盖或与新副本同时开真机。GitHub版未在现有机器人正式部署，旧状态迁移须由维护者处理。

## 4. 一次完整采集

### 4.1 摆场景

先做一个明确任务，例如“把蓝色方块放到红色标识内”。让起点、夹爪接触和放置位置可辨认，避免关键区域长期出画；腕部相机会随手臂移动，需观察整段视野。检查线缆、工作区，先空载熟悉再抓物。

全臂松力没有重力补偿。准备支撑肩肘与末端，夹爪为空，手避开夹缝；不能可靠支撑就不要使用该手拖方式。

### 4.2 设置初始位置

1. 点 **手动设置初始位置**，按提示确认支撑、空夹爪等条件后松力。
2. 手动轻柔摆到合适姿态，看关节反馈，SDK 边界内建议至少留 10° 余量；这不是安全空间认证。
3. 摆稳后点 **保存初始并抱紧**，继续支撑，现场确认已抱紧，再点 **确认已抱紧**。
4. 现场确认后才保存新初始；取消不自动上力，不覆盖旧初始。

第一次没有初始位置也能设置。保存姿态不等于归零或校准。**5秒内回初始** 会真实运动，需先确认抱紧和整条路径，不用它强行从无效反馈 / 松力恢复。

### 4.3 手动示教：只录关节

1. 选任务，点 **进入手动示教**，按提示准备支撑后松力。
2. 可先摆姿态，再点 **开始记录关节**。本条第一帧就是自己的回放起点，不强制等于全局初始。
3. 持续支撑，轻柔完成接近、合爪、抬起、移到目标、张爪、撤离。松力夹爪没有主动抓持力，不能依靠其承重。
4. 示教阶段只录关节与真实时间，屏幕相机只是预览；目标 10Hz，最长 120 秒，不保存视频。
5. 点 **结束示教**，停止拖动、继续支撑，点 **当前位置抱紧**，再现场确认 **已抱紧**。
6. 审核后 **保存人工示教**，或 **删除并重录**。快速变化提示需确认真实动作，不要直接忽略。

短暂无效读数跳过但保留时间差，不用旧读数伪造新点。持续失败或采样长间断会中断，保留异常草稿；异常草稿不能当完整示教保存。恢复读数不自动续录之前片段。

### 4.4 自动执行并采集

1. 保存示教，重新摆好物体。确认抱紧，手与支撑退出整条路径，线缆有余量。
2. 点 **回本条起点并回放采集**，选夹爪补偿 0 / 1 / 2° 并完成现场确认。
3. 相机先预热与实际帧率检查；通过后回本条首帧，再倒计时，限速执行，同时保存图像、实际反馈、真正执行目标。
4. 不再手动拖动或使用其他控制软件。异常会停止后续目标、保留异常数据，不自动回位 / 松力。
5. 结束后等编码和帧数核对，点 **预览本次数据** 看实际任务结果；观看前确认机械臂固定。
6. 不满意可 **重新播放并记录**（只把当前未保存回放移入回收站），或 **删除此人工示教** 后重录。
7. 满意选 **保存此次数据**，人工标注成功 / 失败 / 未标注。之后可下一条。

采集完整性检查通过不代表抓取成功。人工拖动与限速回放也不完全相同，训练动作应读回放 JSONL 的 `action`，不能直接用原手拖角度替代执行命令。

## 5. 夹爪补偿

本机 J6 增大对应闭合。0° 按原轨迹；1 / 2° 按本条开合范围平滑增加：

```text
实际目标 = 原角 + 补偿量 × (原角 - 最小J6角) / (最大J6角 - 最小J6角)
```

最大张开处不变，最闭合处多夹所选角度，中间平滑变化；不是识别抓取时刻或力控。开合不足 5° 拒绝非零补偿，补偿后超过 SDK 范围拒绝，不悄悄截断。

原示教和嵌入副本不改，元数据保留策略，实际目标进入 `action`。可先试 0 / 1°，按现场决定是否 2°。持续嗡鸣、明显变形、发热应停止检查，不用加角度代替抓取位置和接触诊断。

## 6. 单 / 双摄与时序

现有 Orbbec 是带深度能力的设备，但本软件只用 **RGB UVC** 路，没有深度 SDK / 深度 / IR / 点云输出。

请求 MJPG、640×480、30fps，独立线程持续读。本机实际约 29.7fps，每 3 帧选一次形成约 9.9～10Hz。相机卡片显示实际接收帧率；启动、切换、重连或观看退出后等约 3 秒稳定。

一个相机可能有多个 video 节点：本机 `/dev/video1` 是元数据，不是第二台。依据 V4L2 采集能力过滤，优先 `/dev/v4l/by-id/` 标识，避免重启编号变化。

### 双摄操作

1. 接好真正第二台 RGB，例如固定外部视角，腕部仍作主相机。
2. 结束采集、固定机械臂，点相机卡片 **单/双摄**。
3. `wrist` 选腕部 RGB，`overview` 选外部 RGB，不能选择同一设备的不同别名。
4. 应用后等两路实际帧率检查通过，才保存配置；检查双路关键视野，再空载 / 简单任务验收。

> 本GitHub分发不附带界面截图或现场图像。

副相机选最新未消费帧，图像年龄 ≤50ms，主 / 副接收差 ≤35ms，副路相邻保存间隔允许 50～150ms。副路不是严格均匀 10Hz，主机时间配对不是曝光硬件同步。

任一路失效停止后续目标并留异常条目，不静默少录一路；重启缺第二路也不自动降级，需要显式改单摄或接回设备。真实第二台接入后需验证帧率、USB 带宽、供电、配对和视野，模拟通过不等于硬件通过。

视频抖动可能是支架、臂体振动、运动模糊或采样时序，不能一概归因帧率；软件时序改进不能消除全部机械振动。

## 7. 看视频、管理与导出

### 观看

点 **04 已保存视频**，先确认机械臂已抱紧或可靠固定、当前无运动或采集。窗口只查看文件，不执行轨迹，打开期间禁止机械臂控制。

可播放 / 暂停、拖进度、逐帧和 0.5 / 1 / 2 倍速；双摄可切角色。同帧号对应同一动作行，按各路实际接收时间播放；JPEG 缺失时回退相应 MP4。

> 本GitHub分发不附带界面截图或现场图像。

### 数据管理

点 **05 数据管理**，固定确认后进入；可查看完整 / 异常采集、示教、回收站，按编号 / 任务 / 备注搜索，按结果筛选。

> 本GitHub分发不附带界面截图或现场图像。

采集可修改任务、人工结果、备注，保留原任务和修改历史；不改图像、JSONL 或嵌入示教。示教可加备注，原任务保留。

删除只移回收站，可恢复，编号冲突拒绝覆盖。工作区正在引用的条目不可编辑 / 删除，先进入下一条。删除源示教不连带删独立 episode，后者自带 `teaching.json`。

**导出完整ZIP** 后台写到数据根目录 `exports/`，包含图像、视频、JSONL、元数据、原示教及 SHA256 清单。不上传，不覆盖同名文件；关闭窗口请求取消导出。自定义文件名用英文字母、数字、点、下划线、短横线，默认名可直接确认。

ZIP 是单条原始 episode，不是训练格式转换。实际采集可能有现场人物和设备信息，分享真实数据前自行复查；本软件分享包没有附带这些数据。

## 8. 软件急停、异常恢复

### 急停与复位

顶部红色 **软件急停 · F12** 无二次确认，锁定后续位置与扭矩写入并持久化。主要弹窗有触屏急停，F12 只在本应用获得输入时有效。

> 本GitHub分发不附带界面截图或现场图像。

它不切电、不撤销已发送的目标，不保证进程、系统、I2C 或控制板卡死时实际停止，不控制其他程序。原扭矩不变，松力时仍需支撑；不能替代独立硬件急停。

排除故障、固定后点顶部 **复位**，按现场勾选确认。复位不抱紧、不松力、不回位、不续动。状态文件损坏按锁定处理；磁盘写入失败时内存仍锁定，但重启后的持久化可靠性不能保证。

### 松力后读数异常

1. 持续支撑、停止拖动，看关节提示，不盲目回位或回放。
2. **重新检查反馈** 只重读。J3 原始映射负数是诊断，不会当 0° 发送给电机。
3. 需要抱紧时按界面 **当前位置抱紧 / 异常时尝试抱紧** 的现场确认操作。只切扭矩、不发角度目标，仍可能调整，继续支撑；不是每种状态都允许。
4. 抱紧已发但越界无法确认时，按 **支撑后重新松力调整** 的确认，持续承托，轻柔调整回有效范围，再抱紧并现场确认。仅处理本软件记录的直接扭矩模式，不处理旧板载学习模式。
5. 持续无效或卡阻时保持固定检查硬件，不硬掰、不反复盲目上力。异常草稿需删除重录，不拼接成成功条目。

退出不自动上力、松力或回位，重开保留恢复标记；退出前先固定 / 确认抱紧。

## 9. 故障速查

| 现象 | 检查与处理 |
|---|---|
| 反馈在线但按钮全灰 | 先看是否“软件急停已锁定”；排障固定后点顶部复位，再按状态确认抱紧，别直接判界面崩溃 |
| 回初始后不能开始记录 | 回位与松力示教是不同状态；确认抱紧后重新进入手动示教；看待确认、异常反馈、工作区或急停提示 |
| J3 手拖后显示横线 | 可能到 SDK 映射外，按恢复流程处理；不能填旧角或钳位假装有效 |
| 回放夹不住 | 检查接触 / 位置；松力手合爪不是主动夹持，可试补偿但不保证解决 |
| 相机不稳定 | 等预热，检查占用、MJPG / 30fps 能力、光照曝光、USB 带宽；不绕过阈值 |
| 单台列多个节点 | 可能元数据 / 别名，不算独立双摄 |
| 观看或管理时不能控制 | 关闭对应窗口后再操作，这是控制互锁 |
| 条目不能删除 | 工作区正在引用，先进入下一条；删除后回收站恢复 |
| 设备被占用 | 退出另一采集台 / 旧脚本 / APP，不删锁强开 |
| 可读但动作无响应 | 停止重复动作，检查供电、线缆、控制板；系统重启不等于独立控制板断电 |
| 缺 PyQt5 / Arm_Lib | 确认系统 Python 和厂家 SDK，避免环境混用 |
| 无法连接 display | 从机器人已登录图形桌面启动；普通 SSH 不会创建图形会话 |
| 编码失败 | 查磁盘、ffmpeg / ffprobe、encode_wrist.log / encode_overview.log，原帧和 JSONL 保留，不手改 saved |
| 退出仍松力 | 继续可靠固定，软件不自动上力，断电不保证姿态保持 |

运行日志：便携入口 `~/dofbot-data/reports/touch_collector.log`；事件日志：数据目录 `reports/events.jsonl`。诊断结合现场，不仅凭截图推断硬件原因。

## 10. 数据目录与训练语义

```text
数据目录/
  home.json                    全局初始姿态
  work.json                    当前工作区引用
  camera_config.json           已应用的相机配置
  safety.json                  软件急停持久化状态
  teachings/<id>/
    trajectory.json            人工关节示教，无视频
    metadata.json              任务、状态、点数
  episodes/<id>/
    metadata.json              任务、状态、人工结果、来源、相机、补偿与检查
    teaching.json              原始示教副本
    samples.jsonl              每帧一行实际反馈 / 目标 / 时间戳
    frame_timestamps.json      相对采样时间
    images/000000.jpg ...      主相机 RGB
    video.mp4                  H.264，标称10fps
    images_overview/ ...        仅双摄
    video_overview.mp4          仅双摄
    encode_wrist.log           主视频编码日志
    encode_overview.log        仅双摄
  trash/                       软删除
  exports/                     导出ZIP
  reports/                     事件与连接记录
```

目录 id 包含 UTC 时间与随机后缀，界面可能用本地时间；别因时区差手改名称。

| 字段 | 含义 |
|---|---|
| frame_index | 从0开始，视频第n帧对应该帧号 JSONL 行 |
| observation.state | J1～J6 真正 SDK 角度，单位 degree；六关节顺序读，不是硬件同一瞬间 |
| action | 该帧实际生效的绝对关节目标，含补偿；不是末端位姿、力矩或角速度 |
| command_sent | true 本帧发新位置指令，false 保持之前目标 |
| action_write_* | 新指令写入单调时钟纳秒，保持帧为 null |
| active_command_write_* | 当前目标上次真正写入时间 |
| state_read_* | 状态读取起止时间，本帧读取先于新目标写入 |
| cameras.wrist / overview | 每路图像、序号、主机接收时间和图像年龄 |
| camera_pair_skew_ms | 两路主机接收差，不是曝光误差 |
| timestamp | 本条相对采样秒数；跨启动不能直接比较单调时钟 |
| operator_success | 人工 true / false / null，不由采集检查推断 |
| capture_checks_passed | 数据完整性，不是任务成功 |
| train_ready | 原始数据保持 false，待审核和转换 |

视频恒定10fps编码，精确时间看 JSONL；`actual_observation_hz` 记录实际频率。主机接收时刻不是曝光触发时刻。

## 11. 用于 VLA 前还要做什么

**当前不是直接可训练的 LeRobot v3 Parquet 数据集，没有一键训练或已验证转换器。**

先少量采集逐条检查：任务与画面一致；抓放实际成功；接触可见；物体和目标没有长期出画；图像与动作对应；无异常和模拟混入。不要先大量复制同一轨迹再发现视野 / 字段不适合。

后续转换需核对关节顺序、角度单位、绝对位置动作语义、真实时间重采样、相机角色、图像尺寸和标签。按 `teaching_id` 分组划分训练 / 验证，避免同一示教多次回放跨集合泄漏；重复回放不是独立人工示范。

采集设计建议：增加独立物体位置和起始条件变化通常比无限回放一条轨迹更有价值；不保证任何模型的效果。
