# DOFBOT 数据采集台

v0.1.7：新增单/双RGB相机切换、数据管理和持久化软件急停。保留夹爪0°/1°/2°补偿、角度越界手动恢复和已有数据兼容性。

这是一款适配当前 Jetson / DOFBOT-PRO / 1280×800 触摸屏的本机原生应用。使用已安装的 Python 3.10、PyQt5、OpenCV、Arm_Lib 和 FFmpeg，不改变 ROS 环境或全局 Python 包。打开应用不会自动运动或切换扭矩。

## 打开

触摸桌面上的 **DOFBOT 数据采集台** 图标。所有操作在触屏完成，不需要再输入 MOVE、HOLD 等终端命令。若需要从终端启动：

```bash
软件根目录（仓库内 software）/touch_collector/launch.sh
```

开发测试使用 `python3 -m touch_collector.app --demo`。模拟模式有明显标记，不导入 Arm_Lib、不打开 I2C，数据与正式采集目录分开。

## 一次完整采集

1. 看六路关节反馈和相机预览。第一次使用可直接点 **手动设置初始位置**，不需要先有初始姿态。按触屏提示确认支撑和空夹爪后松力，手动摆到合适起点。此时只预览，不记录示教或视频。
2. 摆稳后点 **保存初始并抱紧**，在当前位置恢复扭矩。继续支撑，现场确认已抱紧，再点 **确认已抱紧**，新初始位置才正式保存。取消或失败保留原初始位置；取消不会自动上力，仍松力时需继续支撑并点 **当前位置抱紧**。这是保存关节姿态，不修改舵机零位或标定。
3. 准备可靠支撑、夹爪为空后，点 **进入手动示教**，勾选现场条件，发送松力指令。
4. 在“示教准备”中点 **开始记录关节**。本条以第一帧真实角度作为自己的起点，不要求与全局初始姿态逐关节对齐，也允许在持续支撑、轻柔移动时开始记录。此阶段相机只有预览，不保存图像或视频，也不发送关节位置目标。记录10Hz，点 **结束示教** 即结束，最长120秒。
5. 结束后先持续支撑，点 **当前位置抱紧**。等软件检查反馈稳定，再现场确认 **已抱紧**。可以 **保存人工示教** 或 **删除并重录**。删除会进入本软件回收站，既不自动松力，也不自动运动。
6. 保存示教后，可以 **下一条人工示教**，或重新摆好物体、清空回位路径，点 **回本条起点并回放采集**。软件先回到本条第一帧的真实姿态，再倒计时后按限速轨迹自动执行，同时保存RGB、实际关节反馈和真实控制目标。
7. 回放结束后可选 **重新播放并记录**、**删除此人工示教** 或 **保存此次数据**。还可点 **预览本次数据**，同步查看图像、实际角度和控制目标；这个预览不会驱动机械臂。
8. 保存时人工选择任务成功、失败或未标注。采集检查通过不等于抓取成功。软件不会自动把任务标为成功。

## 单摄 / 双摄切换

相机预览右上角点 **单/双摄**，分别选择腕部主RGB和外部RGB相机；先确认机械臂固定、没有运动或示教，再应用。当前仅一台实体RGB相机时不能应用双摄。通过V4L2设备能力筛除元数据节点，例如当前`/dev/video1`不是第二台相机。优先保存`/dev/v4l/by-id`设备标识，避免重启后video编号变化造成角色交换。

模式成功应用并通过实测帧率检查后，保存`camera_config.json`。两路均使用MJPG、640×480、30fps请求，实际帧率仍需通过检查。应用失败通常重新打开原配置；相机线程无法释放时会报错而不重复打开。重启后若第二路缺失，不静默改成单摄录制：需要显式选择单摄，或连接好第二路。模式在运动、示教、松力/待抱紧确认、观看和管理期间不能改变。

双摄预览左右显示WRIST（主相机）和OVERVIEW（外部相机）。主相机按已有约10Hz时钟选择帧；第二路选最新未消费且不旧于50ms的帧，主/副主机接收时间差要求≤35ms、副相机相邻记录间隔50～150ms，任何一路失效即停止后续动作并保留异常采集，不能将缺路数据标成完整双摄。副路不是严格均匀10Hz，所有时间戳保留；这不是硬件触发、曝光同步或30fps真实性认证。

双摄episode仍只有一份逐帧状态/动作JSONL，包含`cameras.wrist`和`cameras.overview`的图像路径、序号、接收时间和图像年龄，以及`camera_pair_skew_ms`。主视频/图像仍在`video.mp4`和`images/`；第二路在`video_overview.mp4`和`images_overview/`。两路视频均要通过帧数校验后才允许保存完整采集。元数据包含相机模式、角色、设备、同步限制和实际配置。旧单摄episode保持可读。

观看时用播放器顶部下拉框切换主/副相机，保持同一帧号对应同一动作；各路按自己的接收时间播放。原始JPEG缺失时可回退到该路MP4。当前机器尚未接入第二台RGB相机，双摄硬件帧率/USB带宽仍需在接入后验收；模拟双摄测试不等于两台实体相机已验证。

## 数据管理

左侧 **05 数据管理** 进入前确认机械臂已固定；管理期间禁止发送机械臂控制指令，软件急停仍可使用。

- 查看完整/异常采集、人工示教和回收站，按编号、任务、备注搜索，按成功/失败/未标注/异常筛选。
- 采集条目可修改任务标签、人工结果和备注；保留`original_task`和`annotation_history`，不改写原始图像、JSONL或嵌入的示教及哈希，仍保留`train_ready=false`。训练使用审核后的episode任务标签，原始示教任务用于溯源。
- 人工示教可加备注，管理页不改写原始示教任务。源示教被删除后，已保存episode自带原始`teaching.json`，不会连带删除独立episode。
- 删除只移入本软件回收站，可恢复；原编号存在时拒绝覆盖，旧版回收站项目也可识别。当前工作区引用的数据不能修改或删除，先返回采集台选择“下一条”。不提供永久清空按钮。
- **导出完整ZIP** 在后台复制到数据目录的`exports/`，包含视频、图像、状态/动作、元数据、原始示教和每个文件的SHA256清单。默认文件名可直接确认，已有文件不覆盖；关闭管理窗口会请求取消正在进行的导出。可用SSH下载ZIP。导出不是LeRobot训练格式转换，也不会上传网络。

管理功能复用现有`Store`与Qt组件，参考[LeRobot数据操作工具](https://github.com/huggingface/lerobot/blob/main/docs/source/using_dataset_tools.mdx)和[LERO数据管理工具](https://github.com/masato-ka/lero)的episode筛选、标注和删除设计；它们的数据格式/运行环境与本机原始数据不同，因此没有直接用其命令去重排或删除现有数据。相机接口沿用[LeRobot后台读取与最新帧消费](https://github.com/huggingface/lerobot/blob/main/src/lerobot/cameras/opencv/camera_opencv.py)的职责分离，复用本机已测的采集后端，无新增LeRobot依赖。未直接复制第三方源代码。

## 软件急停与硬件急停的区别

顶部红色 **软件急停 · F12** 无需确认，立即设置停止事件并锁定本软件后续位置/扭矩指令；同时写入`safety.json`，重启应用后仍锁定。F12只在本应用中生效，弹窗内也可用；观看、数据管理和设置弹窗另有触屏软件急停按钮。急停中断的示教/采集保留为异常或中断，不能自动成为成功数据。

急停不盲目上力或松力：保持之前的扭矩状态，原本松力时必须继续可靠支撑。已经下发的动作、控制板内部动作或通信中的指令可能继续；它不能在进程卡死、系统死机、I2C卡住、控制板失控或断电时保证实际停住，也不控制外部APP/不合作的其他脚本。它不是安全认证、切电或硬件急停，不能替代独立硬件急停装置。本软件不会为了急停而自动读错误角度再写回当前位置。

排除故障、固定机械臂后，点顶部 **复位**，确认现场状态。复位只解除本软件锁定，不切换扭矩、不续接旧动作、不回位；仍松力时需要按正常恢复流程操作。状态文件损坏按锁定处理；若磁盘写入失败，内存锁定立即生效并显示持久化错误，重启后的记录可靠性不能保证，需要先处理存储故障。

松力没有重力补偿。当前设备的肩肘可能下落，夹爪也没有主动夹持力，不应依靠松力夹爪承重。手拖阶段只能示教路径和开合，实际抓取效果在通电回放时核验。无法可靠支撑时不应使用全臂松力流程，应改用保持扭矩的遥操硬件或键盘遥操。

## 观看已保存的视频

触摸左侧 **04 已保存视频**。观看前逐项确认机械臂已抱紧或可靠固定、能够自行保持姿态，当前没有运动或采集，再点 **开始观看**。示教、松力、抱紧待确认或自动执行期间不能进入观看窗口。

视频库按保存条目的采集时间倒序排列，显示帧数、任务和成功/失败/待标注。点击条目后可以播放/暂停、拖动进度、上一帧/下一帧，以及0.5/1/2倍速观看。默认按该条实际相机接收时间播放，不强制把旧条目中不均匀的图像时间间隔当成100ms。原始图像不存在时从MP4读取对应帧。观看不选择或覆盖当前人工示教、工作草稿，也不修改原数据。

观看窗口打开期间，软件拒绝机械臂控制命令；关闭窗口后才恢复采集操作。当前条目的 **预览本次数据** 同样经过固定确认并使用这个只读播放器。该确认不发送抱紧或回位指令，也不自动授权后续运动。切勿把观看视频当作自动执行轨迹。

## 相机帧率与采样对应

当前Orbbec/V4L2相机采用MJPG、640×480、请求30fps、四缓冲，独立线程持续读取、消费者只取最新图像。实测单缓冲只能约16fps，四缓冲约29.7fps；这是本机测量结果，不推及所有相机。启动时关闭驱动的动态帧率权限，保留原自动曝光、亮度、增益等设置，不固定为会导致画面变暗的手动曝光。

自动回放前要求相机预热并通过实测帧率检查。记录每三个相机帧采一次，跟随实测相机时钟，约9.9～10Hz；控制目标和实际采样时间均保留。图像接收至关节读取开始要求≤50ms，相邻选中图像间隔要求100±20ms；异常时停止后续运动并保留异常条目。主机接收时间不是硬件曝光触发时间，六关节仍为顺序读取，不宣称硬件同步。

相机卡片显示实测帧率和稳定状态。刚打开或观看退出后，可能需要约3秒让接收窗口恢复稳定，再开始新的自动采集。视频仍以标称10fps编码，精确时间用JSONL；`actual_observation_hz`记录实际观测频率，训练导出时需按真实时间统一频率。此版本改善采样时序，不保证机械振动、相机支架松动或运动模糊均被消除。

## 回放夹爪夹紧补偿

点“回本条起点并回放采集”或“重新播放并记录”后，先选择0°、1°或2°补偿，再检查运动路径。0°完全按原轨迹；触屏默认建议先试1°，本次窗口记住上次选择。底层CLI/Engine未显式指定时仍默认0°，不静默改变旧调用行为。

根据[DOFBOT-PRO厂商说明](https://www.yahboom.net/study/DOFBOT-Pro/17606/)，J6角度增大对应闭合。以本条示教的最小J6角为最大张开角、最大J6角为最闭合角，采用`目标=原角+所选补偿×(原角-最小角)/(最大角-最小角)`。最大张开角不变，最闭合处多夹所选角度，中间以及张开过程平滑过渡；这是角度范围缩放，不是根据图像识别抓取时刻，也不是力控。源轨迹开合不足5°时拒绝非零补偿，避免把反馈抖动当成开合；可选0°或重录。补偿超过SDK的180°时拒绝，不截断掩盖问题。

补偿在逐段限速和重采样之前应用，仍保留原来的10°/s和单步≤2°限制；回本条起点使用本次实际执行计划的第一点，不改变全局初始位置。原始`trajectory.json`和episode的`teaching.json`保持原样及原始哈希；`metadata.json.gripper_compensation`记录公式、开合角和补偿量，JSONL的`action`记录实际下发的补偿后目标，`observation.state`仍是真实反馈。

先试1°，确认夹持效果后再考虑2°。补偿不能保证抓牢，也不修复物体错位、机构间隙或夹指打滑。厂商提醒夹持角过大可能堵转损坏舵机；出现持续嗡鸣、变形或异常发热应停止，不继续加角度。

## 回到初始状态和5秒窗口

“5秒内回初始”请求约4.5秒的同步五次平滑插值，再进行目标检查。3秒现场倒计时另计。默认软件限速30°/s、加速度90°/s²，**这些是软件配置限制，不是厂商额定性能声明**。若跨度要求超过软件限制，则拒绝执行，不通过提高速度来硬凑5秒。USB/I2C延迟、跟踪不足或故障也可能导致中止，所以不能对任意姿态、负载保证实际5秒完成。

回位没有自动避障能力。每次执行前必须检查完整运动路径和线缆，不只是起点和终点。打开软件、选择轨迹、保存、删除和切换下一条均不自动回位。全局“初始位置”和每条记录的“实际起点”分开保存；选择旧示教不覆盖全局初始位置。全局回位按钮返回你设置的初始位置，自动回放返回该条自己的第一帧。

准备页面始终根据扭矩状态提供操作：松力时可开始记录，已抱紧时可进入手动示教。当前位置抱紧并确认后、或回位后，不会继续显示不能操作的“松力准备”。可反复进行“回位→松力→记录→结束→抱紧→下一条”。

**停止动作** 只停止发送后续指令，不自动松力；已经发送的约100ms动作可能继续完成。关闭时也不自动松力或上力。松力、抱紧指令待确认的状态会持久保存，重新打开仍要求恢复/确认。

## 数据目录

正式数据：`~/dofbot-data/datasets/touch_collector/`

```text
home.json                    当前使用的初始姿态
work.json                    当前示教/采集草稿指针
teachings/<id>/
  trajectory.json            人工示教的关节角度与时间（无视频）
  metadata.json              状态、任务、采样点数
episodes/<id>/
  metadata.json              保存状态、人工结果、完整性、来源哈希
  teaching.json              原始示教副本，避免删源轨迹后断引用
  video.mp4                  640×480、10fps、H.264
  images/000000.jpg ...       原始RGB帧
  samples.jsonl              每帧对应的实际角度、真实下发目标及时间戳
  frame_timestamps.json       每帧采样时间
  encode.log                 视频编码日志
trash/                       被删除的人工示教与未保存重录版本
reports/                     只读连接审计
```

视频第n帧与JSONL的`frame_index=n`对应。视频是恒定10fps；精确采样时间使用JSONL，不把收到帧的主机时间假称为传感器曝光时间。`action`为该帧实际生效的关节目标；`command_sent=true`表示这帧发送了新指令，并记录真实写入时间。目标未变化时不重复发送，`command_sent=false`、本帧写入时间为null，`active_command_write_*`引用上次真实指令。图像和反馈仍以10Hz采样，不将保持目标虚构为新的总线写入，也不将手拖角度冒充自动执行指令。

这些是可审核的完整原始episode，**还不是直接可训练的LeRobot v3 Parquet数据集**。`train_ready=false`保留到人工审核、导出和训练配置核对之后。未标注、失败、中断和模拟数据都应分别处理。软件没有自动上传功能。

删除是本软件数据范围内的可恢复移动，不删除厂家工程、旧CLI数据或此前已保存的完整episode。重录只将当前未保存版本移入回收站，已保存的版本保持独立。应用重启后恢复当前草稿，录制/编码途中退出的条目标为中断，不自动变成成功数据。

## 设备独占与故障

应用和旧采集/运动脚本共用`.teleop_record.lock`，防止同时写I2C。图形界面运行时，旧`arm_control.py`会拒绝并提示在图形界面查看状态。若出厂APP/手柄占用设备，界面可在明确确认后“接管出厂控制”，只结束匹配的出厂进程，释放相机，不发送运动命令。

驱动在相邻I2C事务之间保留至少3ms主机间隔，目标没有变化时不重复写入。它们用于降低控制器访问压力，不是控制板复位方法。若出现角度仍能读取但多次小幅指令无实际响应，应停止运动诊断，不盲目连续重发；普通系统重启不等于独立控制板断电。

单个关节SDK返回无效时只重试一次，不填入历史角度或把越界角度夹成0°。界面分别显示每个关节的状态；原始映射值仅用于诊断，不能授权位置运动。SDK范围不是防碰撞范围，手动示教时建议在边界内留至少10°余量。

示教中短暂读数失败会跳过无效观测，保留真实时间戳，不压缩丢帧时间。连续3次失败或本次连续失败持续350ms时中断并保存异常草稿；有效样本间隔超过500ms也会中断。相邻角度变化超过10°时保留原始观测并标为待人工审核，保存时须明确确认属于真实动作；自动回放逐段重定时，保持至多10°/s和重采样单步≤2°，不把录制阶段的速度直接用于执行。异常草稿不能保存为可回放示教，需要删除后重录。读数恢复不会自动续接异常条目，也不会自动切换扭矩。相机预览不依赖关节读取成功，故障时仍继续更新。

自动运动监测最近450ms已发送目标的角度包络（额外3°量化/测量容差），并要求本次目标与当前反馈每关节相差≤12°。反馈落后过久、离开轨迹包络或目标距离超限会停止；终点仍须在2°以内。该监测不代替碰撞检测，也不代表真实机械臂已无硬件问题。

**反馈异常且仍松力时**，保持可靠支撑。可点 **重新检查反馈**；也可点 **异常时尝试抱紧**，按触屏要求确认支撑、空夹爪和手避开夹缝，再发送厂商的当前位置扭矩开启指令。此恢复入口只切换扭矩，不发送任何角度目标；可能有位置调整，需要现场观察。它不会声称角度有效或自动确认抱紧。继续支撑，等待读数恢复，再根据现场状态点 **确认已抱紧**；反馈未恢复前禁止自动回位和回放。若一直没有有效反馈，维持支撑并检查硬件，不强掰、不盲目反复上力。此入口不适用于旧板载学习模式。

**抱紧指令已发、角度越界导致无法确认时**，可点 **支撑后重新松力调整**。必须先确认肩肘和末端已可靠支撑、夹爪为空，并准备持续承托；这会发送一次全臂扭矩关闭指令，没有重力补偿。此恢复不要求先取得有效角度，因为不发送位置目标；只适用于本软件已有的`torque_switch`松力记录，不处理旧板载学习模式。松力后轻柔调整异常关节回有效范围，建议离边界至少10°；有机械阻挡不要硬掰。然后点 **当前位置抱紧**，按现场状态 **确认已抱紧**。异常草稿仍保留且不能变成有效示教，需删除重录；原初始姿态和已保存数据不改。取消确认不切换扭矩。重启保留恢复标记，通信失败不会假称已抱紧。无需重启整机，也不修改舵机零位。

恢复入口依据[厂商扭矩接口说明](https://www.yahboom.net/study/DOFBOT-Pro/12504/)：关闭扭矩允许手动调整，开启扭矩保持当前位置。没有采用零位校准或读数钳位来隐藏越界。该入口消除软件互锁，不能替代现场支撑或修复机械故障。

停止与存储异常均在设备线程的异常处理范围内；写入异常不会静默继续有效录制。自动运动仍采用原先更严格的反馈、相机与控制循环时限，异常时停止后续指令，不自动做额外回位。

程序日志：`~/dofbot-data/reports/touch_collector.log`。关节失效/恢复、示教中断和恢复指令事件记录在数据目录下的`reports/events.jsonl`，含时间、状态、各关节反馈与原因，达到5MB保留一个前序版本。本软件的`home.json`是当前使用的初始姿态，不是旧命令行历史文件的全局归中设置。
